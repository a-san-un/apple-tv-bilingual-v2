# Product Requirements

## 1. プロダクトの目的

Apple TV+ の再生画面で、学習言語と母国語の字幕を並行して見ながら視聴できるようにする Chrome 拡張を提供する。

v2 では、右側字幕 panel を中核 UI とする最小構成から始める。  
字幕取得から表示までの経路、再生対象切替時の再初期化、session 単位の cleanup を破綻なく扱えることを前提に、まずは「Apple TV+ 実画面で継続利用できる最小価値」を成立させる。

この最小実用版で目指す価値は次の通りである。

- 学習言語字幕を視認しやすい形で追える
- 必要に応じて母国語字幕も同時に参照できる
- 再生画面の中で、字幕の現在・過去・未来を右側 panel でまとめて確認できる
- 再生対象の切替、再初期化、拡張 ON/OFF に対して不安定になりにくい

## 2. 対象ユーザー

対象ユーザーは、Apple TV+ を使って字幕付きで語学学習したい視聴者である。

とくに次のようなユーザーを主対象とする。

- 学習言語の字幕を主に読みたいユーザー
- 必要なときだけ母国語字幕を補助的に参照したいユーザー
- 再生中の一行だけでなく、直前と直後の字幕文脈も見たいユーザー
- Apple TV+ 標準 UI だけでは字幕学習に不足を感じているユーザー

初期版では、複雑な学習支援機能を広く提供するよりも、Apple TV+ 再生画面で安定して二言語字幕を確認できることを優先する。

## 3. 解決したい課題

Apple TV+ の標準視聴体験だけでは、語学学習向けの字幕参照体験が不足しやすい。

解決したい主な課題は次の通りである。

- 学習言語字幕を追いながら、必要なときだけ母国語字幕を見比べにくい
- 現在の字幕だけでは前後の文脈を把握しにくい
- 学習用途では、字幕の履歴と少し先の行をまとめて確認したい
- Apple TV+ 側の再生画面は SPA 遷移や再生対象切替があり、拡張側の状態管理が崩れやすい
- 字幕 panel の表示制御、拡張全体の有効 / 無効、再生中だけ必要な一時状態を混ぜると不安定化しやすい

v2 では、これらの課題に対して、右側字幕 panel と最小限の制御 UI に責務を絞って対処する。

## 4. 主要ユースケース

### 4.1 学習言語を主に見ながら視聴する

ユーザーは popup で学習言語を選択し、Apple TV+ の再生画面で拡張を ON にする。  
右側字幕 panel で current / past / future の字幕を見ながら、学習言語字幕を主に追う。

### 4.2 母国語字幕を補助として参照する

ユーザーは必要に応じて母国語を設定し、学習言語と対になる secondary 字幕を参照する。  
母国語が未選択の場合は、ブラウザ言語を fallback として使い、secondary 字幕の解決に利用する。

### 4.3 視聴中に panel を開閉する

ユーザーは拡張を ON にしたまま、右側字幕 panel の開閉ボタンで panel 表示だけを切り替える。  
このとき、拡張全体の有効 / 無効を切り替える ON/OFF toggle と、panel 自体の開閉は別の役割として扱う。

### 4.4 必要なときだけ拡張全体を無効化する

ユーザーは再生画面下部の ON/OFF toggle で、拡張機能全体の有効 / 無効を切り替える。  
OFF の間は、拡張由来の字幕処理・監視・描画は停止し、panel も表示しない。

### 4.5 再生対象が切り替わっても破綻せず使う

ユーザーが別エピソードや別作品へ移動した場合でも、前の再生対象に紐づく一時状態を引きずらず、新しい再生対象に対して再初期化できる。  
これにより、視聴の継続中に字幕表示や UI が壊れにくい状態を維持する。

## 5. 最小実用版の機能範囲

最小実用版で扱う範囲は次の通りとする。

### 5.1 設定

- popup で学習言語を設定できる
- popup で母国語を任意設定できる
- 学習言語は必須とする
- 母国語は学習言語と同じ値を選べない
- 母国語が未選択の場合はブラウザ言語を fallback として使う
- 設定キーは `primaryLang` と `secondaryLang` を基本とする
- 保存設定は再生中だけ使う runtime state と分離して扱う
- UI の候補言語は固定一覧から選ぶ
- 実際の字幕 track 解決は content 側で行う

設定の詳細仕様は `docs/settings-spec.md` で定義する。

### 5.2 再生画面での字幕処理

- Apple TV+ 再生画面と video を解決できる
- primary subtitle を取得できる
- secondary subtitle を取得できる場合は合わせて扱える
- primary / secondary の対応をもとに `SubtitleBlock[]` を構築できる
- `SubtitleBlock[]` から current / past / future を導出して表示できる

アーキテクチャと責務分離の詳細は `docs/minimal-panel-architecture.md` で定義する。

### 5.3 UI

- 右側字幕 panel を表示できる
- panel 内で current / past / future を確認できる
- 再生画面下部に拡張全体の ON/OFF toggle を表示できる
- 右側字幕 panel に panel 自体の開閉ボタンを表示できる
- ON/OFF toggle と panel 開閉ボタンは別の状態・別の役割として扱う
- panel を開いたとき、既存 UI を含む再生画面領域と panel を 7:3 で分割できる
- 7:3 の分割は固定幅ではなく、利用可能な横幅に応じて responsive に計算する

### 5.4 起動時と状態の初期方針

- 拡張全体の ON/OFF 状態を、全作品共通の1つの設定として保存する
- ON/OFF の保存値がない場合は、ON を既定値とする
- 保存値がある場合は最後に選んだ ON/OFF を復元し、作品・エピソードの変更では変更しない
- ページ再読み込み・ブラウザ再起動後も、保存された ON/OFF を復元する
- 拡張を ON にしたとき、および ON の状態で新しい視聴を開始したときは、panel を開く
- 視聴中は、拡張を ON にしたまま panel だけを開閉できる
- panel の開閉状態は保存しない
- 同じ視聴の技術的な再接続では、手動で変更した panel の開閉状態を維持する

### 5.5 再初期化と cleanup

- 再生停止、再初期化、再生対象切替時に session 単位で cleanup できる
- listener、timer、observer、track binding、DOM、runtime state を解放できる
- 前の再生対象に属する字幕データ、DOM、video・track 参照などを次の再生へ持ち越さない
- 全作品共通の ON/OFF 設定は、再生対象の終了・変更・再初期化では変更しない

実装の進め方は `docs/implementation-workflow.md`、確認観点は `docs/testing-checklist.md` で定義する。

## 6. 最小実用版では扱わない範囲

最小実用版では、次の機能や論点は対象外とする。

- 学習補助 overlay
- 単語辞書 popup
- AI を使った補助表示
- 統計 UI
- 外部 API 連携
- 詳細な options 画面を前提とした多機能設定
- 大規模な state 管理ライブラリ
- UI ライブラリ導入を前提にした設計
- 過度な見た目調整や装飾目的の UI 強化
- Apple TV+ 固有の複雑な補助機能を広く先取りすること
- panel 開閉状態の永続化

この文書では、アーキテクチャ詳細、設定の詳細仕様、実装手順、テスト詳細は扱わない。

詳細は次の正本文書で定義する。

- 設定仕様: `docs/settings-spec.md`
- アーキテクチャ: `docs/minimal-panel-architecture.md`
- 実装手順: `docs/implementation-workflow.md`
- テスト: `docs/testing-checklist.md`

## 7. 今後の拡張方針

初期版の対象外機能を将来追加する場合でも、まず最小実用版として成立している価値を壊さないことを優先する。

拡張時のプロダクト方針は次の通りとする。

- 初期版の対象外機能を追加する場合も、まず二言語字幕を安定して視聴できる最小価値を維持する
- UI を増やすこと自体を目的にしない
- 新しい機能や UI は、学習言語字幕の視認性、母国語字幕の補助参照、字幕文脈の確認という中核体験を強める場合に限って追加を検討する
- 拡張候補は MVP の完了条件とは混ぜず、将来スコープとして別に扱う

## 8. 非機能要件

最小実用版では、機能の有無だけでなく、再生画面で継続利用できる安定性を重視する。

非機能要件は次の通りとする。

### 8.1 安定性

- Apple TV+ 再生画面で継続して利用できること
- 再生対象切替や再初期化のたびに state が破綻しにくいこと
- session 単位で開始と停止を明確に扱えること

### 8.2 cleanup の明確さ

- listener、timer、observer、track binding、DOM、runtime state の解放責任が曖昧でないこと
- 前 session の参照が残り続けないこと
- OFF 時に字幕処理・panel 表示・layout 適用と、それらに必要な監視を停止できること
- OFF から ON に戻すための操作経路は利用できること

### 8.3 責務分離

- 保存設定と runtime state を分離すること
- UI 候補言語と実際の track 解決を分離すること
- 拡張全体の有効状態と panel 開閉状態を分離すること

### 8.4 追いやすさ

- TypeScript に不慣れでも追いやすい最小構成であること
- 用語が一貫していること
- MVP の機能範囲が過不足なく限定されていること

### 8.5 レイアウトの一貫性

- 右側字幕 panel を開いたとき、既存 UI を含む再生画面領域を前提にレイアウトできること
- 小さな横幅でも固定値で無理に押し込まず、利用可能幅に応じて扱うこと

## 9. 最小実用版の完了条件

この文書における最小実用版の完了条件は次の通りとする。

### 9.1 ユーザー価値としての完了条件

- ユーザーが popup で学習言語を設定できる
- ユーザーが必要に応じて母国語を設定できる
- Apple TV+ 再生画面で拡張を ON にすると、右側字幕 panel で二言語字幕を確認できる
- panel 上で current / past / future の字幕文脈を確認できる
- ON/OFF toggle と panel 開閉ボタンの役割差が UI 上で明確である

### 9.2 振る舞いとしての完了条件

- 学習言語必須、母国語任意、同一言語禁止、ブラウザ言語 fallback が成立している
- `primaryLang` / `secondaryLang` を保存設定として扱えている
- ON/OFF 状態を全作品共通で保存し、未保存時は ON、保存済みの場合は最後に選んだ値を復元する
- ON にしたときと、ON の状態で新しい視聴を開始したときに panel を開く
- panel の開閉状態を保存せず、視聴中は拡張を ON にしたまま panel だけを開閉できる
- 同じ視聴の技術的な再接続では、手動の panel 開閉を維持する
- primary / secondary 字幕から `SubtitleBlock[]` を構築し、panel 表示へ使えている
- panel 表示時に 7:3 レイアウトを適用できる
- OFF、再初期化、再生対象切替時に cleanup が成立する

### 9.3 スコープ管理としての完了条件

- MVP 対象外の機能を混ぜずに、最小範囲で成立している
- この文書単体で、対象ユーザー、主要ユースケース、MVP の機能範囲、対象外範囲、非機能要件、完了条件を判断できる
- 設定仕様、アーキテクチャ、実装手順、テストの詳細参照先が明示され、役割が重複していない
